- **Model / endpoint:** `qwen3.8-27b-sglang` at `http://127.0.0.1:8888/v1/chat/completions`
- **Run:** 2026-08-19 20:08, single DGX Spark (GB10, 121.7 GiB unified), 262,144-token KV pool, 8 concurrent slots, thinking off unless stated

## Headline

- **Single-stream spread: 25.2 → 60.4 tok/s** (2.39×), free-form prose to step-by-step math / reasoning — this spread *is* the speculative-decoding story.
- **Usable peak: 194.5 tok/s** at 8 concurrent streams (283 ms TTFT). 16 streams nudges aggregate to 197.7 but TTFT to 6204 ms, so it is not a win.
- **Radix cache: 11.86× faster TTFT** on a shared prefix (2289 ms cold → 193 ms warm).
- **Thinking costs almost nothing:** 53.68 tok/s off vs 52.43 on.
- **Acceptance: 3.98 tokens per verification pass** (range 2.23–7.08 over 78 decode batches, ceiling 8).

Decode rate tracks how *predictable* the output is, not how hard the task is. Structured and mathematical output lets the block drafter land; free-form prose does not, and you pay for the discarded draft anyway.

## 2. Concurrency scaling

*300 tokens per stream.*

| Streams | Aggregate tok/s | Per-stream | Avg TTFT (ms) | Wall (s) |
|:---|:---:|:---:|:---:|:---:|
| 1 | **40.09** | 40.09 | 158.8 | 7.48 |
| 2 | **68.10** | 34.05 | 185.4 | 8.81 |
| 4 | **114.41** | 28.60 | 219.2 | 10.49 |
| 8 | **194.48** | 24.31 | 282.6 | 12.34 |
| 16 | **197.72** | 12.36 | 6204.3 | 24.28 |

**Throughput plateaus at 8.** Going to 16 moves aggregate 194.5 → 197.7 tok/s — flat — while average TTFT degrades 22× (283 → 6204 ms), because `--max-running-requests 8` admits eight and the rest queue. Past eight you must raise *both* that and the GDN pool (`concurrency × 5` slots); raising one alone clamps back.

## 4. Radix prefix cache

| Condition | Shared prefix tok | TTFT |
|:---|:---:|:---:|
| Cold (0% hit) | 4,787 | 2289.4 ms |
| Warm (100% hit) | 4,787 | **193.0 ms** |

**11.86× on TTFT.** This is why concurrent subagents sharing a system prompt cost far less than N× a single agent: the shared prefix is stored and prefilled once.

## 6. Thinking on vs off

| Mode | Completion tok | Reasoning tok | TTFT (ms) | Decode tok/s |
|:---|:---:|:---:|:---:|:---:|
| Thinking off | 512 | 0 | 207.6 | **53.68** |
| Thinking on | 512 | 512 | 211.0 | **52.43** |

Speculative decoding is as effective on chain-of-thought tokens as on the answer. Thinking costs *tokens*, not throughput — and the checkpoint defaults to `xhigh`, so disable it explicitly with `chat_template_kwargs: {"enable_thinking": false}` unless you want it.

## 7. Speculative acceptance

Parsed from SGLang telemetry over the run window: **mean 3.98**, median 3.96, range 2.23–7.08 across 78 decode batches. Block size is 8, so 8.00 is the ceiling.

That single number explains every table above: at 7.1 accepted tokens per pass the model emits 3.2× more per weight-streaming pass than at 2.2. Decode here is memory-bandwidth-bound, so accepted-tokens-per-pass is almost the whole story.

## Reproducing

```bash
scripts/bench-standard-suite.py \
    --url http://127.0.0.1:8888/v1/chat/completions \
    --model qwen3.8-27b-sglang \
    --output results/standard-benchmark-results.json
scripts/render-benchmark-report.py
```

Run on an otherwise idle machine — a co-tenant GPU job depresses the concurrency numbers badly, and an earlier round of measurements had to be discarded for exactly that reason.
